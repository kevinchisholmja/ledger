# 2026-06-01 — Logout Bug Fixes (React Error #300 + #418)

Activity log for June 1st documenting the investigation and resolution of two
React runtime errors triggered on logout.

---

## Bug — React Error #300 on Logout (Rendered more hooks than previous render)

- [bug] Clicking "Sign out" crashed the app with React minified error #300.
  Chrome DevTools confirmed: "Rendered more hooks than during the previous render."
  This is a violation of the Rules of Hooks — hooks must be called in the same
  order on every render.

- Root cause: `app/components/UploadButton.tsx` had four `useState` calls declared
  **after** an early return:

  ```tsx
  export default function UploadButton() {
    const router = useRouter();
    const pathname = usePathname();
    const inputRef = useRef<HTMLInputElement>(null);

    if (pathname === "/login") return null;   // <-- early return

    const [uploadState, setUploadState] = useState<UploadState>("idle");  // AFTER early return
    const [errorMsg, setErrorMsg] = useState("");
    const [menuOpen, setMenuOpen] = useState(false);
    const [showForm, setShowForm] = useState(false);
  ```

  When navigating to `/login` after logout, the early return fires on the first
  render, meaning React calls only 3 hooks. On any other page it calls 7. React
  loses track of hook identity between renders, causing error #300.

- [fix] Moved all four `useState` declarations above the early return so they
  are always called in the same order regardless of pathname:

  ```tsx
  export default function UploadButton() {
    const router = useRouter();
    const pathname = usePathname();
    const inputRef = useRef<HTMLInputElement>(null);
    const [uploadState, setUploadState] = useState<UploadState>("idle");
    const [errorMsg, setErrorMsg] = useState("");
    const [menuOpen, setMenuOpen] = useState(false);
    const [showForm, setShowForm] = useState(false);

    if (pathname === "/login") return null;   // early return now safe
  ```

  File changed: `app/components/UploadButton.tsx`

## Bug — React Error #418 on Logout (Hydration Mismatch)

- [bug] After fixing error #300, a new error appeared: React minified error #418
  ("Hydration mismatch — server-rendered HTML does not match client render").
  This occurred when landing on `/login` after logout.

- Root cause: `app/components/ThemeToggle.tsx` rendered different icons on the
  server vs. the client. The component used:

  ```tsx
  {mounted && isDark ? <Sun /> : <Moon />}
  ```

  On the server, `mounted` is always `false`, so `<Moon />` is always rendered.
  On the client, after `useEffect` fires, `mounted` becomes `true` and — if the
  user's resolved theme is dark — `<Sun />` is rendered. React detects the
  mismatch between the server HTML and the first client render and throws #418.

- [fix] Return a placeholder button (empty `<span>`) before `mounted` is true,
  so both server and client render an identical empty icon slot on first paint.
  After mount, the real icon (Sun or Moon) is rendered:

  ```tsx
  if (!mounted) {
    return (
      <button ...>
        <span className="size-4" />
        <span className="sr-only">Toggle theme</span>
      </button>
    );
  }
  // Safe to read resolvedTheme now
  const isDark = resolvedTheme === "dark";
  ```

  File changed: `app/components/ThemeToggle.tsx`

## Additional fixes

### Logout redirect — router.push → window.location.href
- [fix] `app/components/Sidebar.tsx` and `app/components/MobileNav.tsx`:
  replaced `router.push("/login")` with `window.location.href = "/login"` after
  `supabase.auth.signOut()`. Full page reload avoids any React re-render or
  stale-state issues during the auth→unauth transition. `useRouter` import
  removed from both files.
- [fix] `app/components/LogoutButton.tsx`: same `window.location.href` change
  (already applied in the earlier session).

### Cursor pointer on logout buttons
- [fix] Added `cursor-pointer` class to the Sign out `<button>` in both
  `app/components/Sidebar.tsx` and `app/components/MobileNav.tsx`. The browser
  default for `<button>` is `cursor: default` in some configurations; this makes
  the intent explicit and consistent with all other interactive elements.

### Sidebar email hydration mismatch
- [fix] `app/components/Sidebar.tsx` displayed `{email ?? ""}` which could differ
  between server (always empty) and client (potentially populated after useEffect).
  Added a `mounted` state check so the email is only rendered client-side after
  hydration is complete: `{mounted ? (email ?? "") : ""}`. This prevents React
  from detecting a text content mismatch during hydration.
