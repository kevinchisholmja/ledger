# 2026-05-24c — Production Bug Fixes

Post-deployment debugging session. Three bugs found and resolved after the first
production login attempt.

---

## [bug] Magic link redirecting to localhost:3000

Clicking the Supabase magic link email redirected to `localhost:3000` instead of
the production URL, with `error=access_denied&error_code=otp_expired`.

[fix] Two Supabase Dashboard changes (no code change):
1. Authentication → URL Configuration → **Site URL** changed from
   `http://localhost:3000` to `https://ledger-gules-seven.vercel.app`
2. Added `https://ledger-gules-seven.vercel.app/api/auth/callback` to **Redirect URLs**

Root cause: Supabase constructs the magic link using Site URL. If `emailRedirectTo`
is not in the Redirect URLs allow-list, Supabase ignores it and falls back to Site URL.

---

## [bug] "Failed to fetch" on login + "Something went wrong" on dashboard

After the Site URL fix, the login page showed "Failed to fetch" and the dashboard
showed a Server Component error (`Error: Fa…` in Vercel logs).

[fix] Triggered a production redeployment (`vercel --prod`).

Root cause: `DATABASE_URL` and `NEXT_PUBLIC_SUPABASE_ANON_KEY` were added to Vercel
5 hours after the original production deployment. The running build had `undefined`
for both:
- `NEXT_PUBLIC_SUPABASE_ANON_KEY` undefined in the browser bundle → `signInWithOtp`
  fetch failed
- `DATABASE_URL` undefined at runtime → Drizzle connection failed

`NEXT_PUBLIC_*` vars are baked into the build at compile time. Adding them to Vercel
after deployment does not update the running build — a redeployment is required.

## [bug] Dashboard crash: `column "amount" does not exist` on buckets

After logging in successfully, the dashboard crashed with:
```
[cause]: db: column "amount" does not exist
```

Query: `select "id", "user_id", "name", "period", "amount", ... from "buckets"`

[fix] Migration `20240005_fix_buckets_schema.sql` applied directly via postgres connection:
1. `alter table public.buckets rename column allocated_amount to amount`
2. `alter table public.buckets add column category_id uuid references public.categories(id)`
3. `alter table public.buckets add column updated_at timestamptz default now()`
4. Dropped and recreated `buckets_summary` view — it referenced `b.allocated_amount`
   in two places (`CREATE OR REPLACE` cannot rename view columns; required drop + recreate)

Root cause: The Phase 1 migration created `buckets.allocated_amount` but the Drizzle
schema (written in Phase 3) used `amount`. The discrepancy was never caught because
the database was only queried for the first time after production login.

→ `supabase/migrations/20240005_fix_buckets_schema.sql`

Redeployed after migration. Dashboard loads correctly.

## [note] Supabase email rate limit — 2 emails/hour

Supabase free tier uses shared SMTP capped at 2 magic link emails per hour per project.
Hit this limit during debugging (sent 3 OTP emails in rapid succession).

The limit is visible at: Authentication → Configuration → Rate Limits →
"Rate limit for sending emails".

The value (2/h) is not editable on the free tier. To remove the cap:
Authentication → SMTP Settings → configure a custom SMTP provider (e.g. Resend).

This is not a bug — it is expected behaviour. Added to ToDo.md as a deferred improvement.
