# 2026-05-27c

## Phase A5a — Type-Aware Entry Form + Payee Autocomplete

First batch of new features enabled by the v2 `transactions` table.
Adds manual transaction creation for all 8 transaction types without requiring
a receipt upload.

---

### New API routes

**`app/api/payees/route.ts`** (NEW)
- `GET /api/payees` — lists all payees for the authenticated user, ordered by name
- Used by `TransactionEntryForm` to populate the payee datalist

**`app/api/transactions/route.ts`** (NEW)
- `POST /api/transactions` — creates a single non-transfer transaction
- Types handled: `purchase`, `income`, `refund`, `chargeback`, `bank_fee`,
  `interest`, `opening_balance`
- Direction is derived from type server-side (no client trust needed)
- Payee lookup/create: if `payee_name` matches an existing payee by name, links
  via `payee_id`; otherwise creates a new payee row
- All manual entries insert with `source: 'manual'`, `status: 'confirmed'`,
  `cleared: true`

**`app/api/transactions/transfer/route.ts`** (NEW)
- `POST /api/transactions/transfer` — creates a matched transfer pair
- Inserts `transfer_out` leg first, then `transfer_in` leg with
  `transfer_pair_id = outgoing.id`, then updates outgoing to set
  `transfer_pair_id = incoming.id` (both legs point to each other)
- Returns `{ outgoing, incoming }` with both transaction objects

### New components

**`app/components/TransactionEntryForm.tsx`** (NEW)

Type-aware modal form. Type selector is always the first field; everything
else renders conditionally based on the selected type.

| Type | Account | To Acct | Payee | Category | Budget | Inv Date | Ref # |
|---|---|---|---|---|---|---|---|
| purchase | ✓ | — | ✓ | expense | ✓ | ✓ | ✓ |
| income | ✓ | — | ✓ | income | — | ✓ | ✓ |
| transfer_out | From | To | — | — | — | — | ✓ |
| refund | ✓ | — | ✓ | expense | ✓ | — | ✓ |
| bank_fee | ✓ | — | — | — | — | — | — |
| interest | ✓ | — | — | — | — | — | — |
| chargeback | ✓ | — | ✓ | expense | — | — | ✓ |
| opening_balance | ✓ | — | — | — | — | — | — |

**Payee autocomplete + learning:**
- `<datalist>` fed from `GET /api/payees` — native browser autocomplete
- When typed payee name matches an existing payee (case-insensitive), the form
  auto-fills `category_id` and `bucket_id` from the payee's defaults
- New payees are created silently on first use via the transactions route

**Data loading:** fetches accounts, categories, budgets, payees in parallel on
mount. Default account auto-selected; currency follows the selected account.

**Transfer UX:** "From Account" and "To Account" shown side by side; to-account
list excludes the selected from-account.

**Validation:** client-side checks for account, amount > 0, date, and
(for transfer) destination account before hitting the API. Error shown inline.

**`app/components/UploadButton.tsx`** (UPDATED)

FAB now opens a two-option menu instead of immediately triggering file input.

- Tap `+` → menu appears with backdrop click-away
- "Add manually" → opens `TransactionEntryForm` modal
- "Upload receipt" → opens file picker (existing OCR flow unchanged)
- FAB label changes to "Add" (was "Upload receipt"); shows `×` when menu open
- `TransactionEntryForm` rendered inside `UploadButton` controlled by `showForm` state

### What Phase A5a does NOT include (deferred to A5b)
- Payee default learning (updating `default_category_id` after N uses)
- Receipt attachment on manual entries
- Per-account register (`/accounts/[id]`)
- Plan page revamp (TBB, Assigned/Spent/Available)
- Flag for accountant toggle
- Reconciliation workflow
- OCR income/refund detection
