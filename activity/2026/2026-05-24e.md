Three distinct things done in this session: established the design direction,

through War Room.

## [feature] Design north star — Copilot Money

Researched the most highly rated budgeting and expense tracker apps to establish
a design reference before War Room could prescribe another generic dark-theme brief.

Apps evaluated:
- **Copilot Money** — iOS/macOS only, built to Apple design standards, universally
  considered the best-designed budgeting app. Horizontal progress bars per category,
  colour-coded green/amber/red by spend %, clean typography, smooth animations.
- **Monarch Money** — best overall dashboard design, customisable widget cards,
  clean category list with budget vs. spent columns, recently refreshed with better
  information density.
- **YNAB** — not the prettiest but the most studied. Envelope model (give every
  dollar a job) maps directly to Ledger's budget concept.

[decision] **Copilot Money is the design north star.** Adopt its structure and
patterns, not its light-mode colours. Key patterns to carry forward into the P4
UI pass:
- Progress bar list layout (category tab): spent left, budget right, bar fills
  between them, colour changes with spend level
- Circular budget indicators on the dashboard (over/under amount shown below each)
- Transaction rows: merchant dominant, category as a small coloured pill, amount
  right-aligned
- "TO REVIEW / view all" section header pattern for the pending banner

Created `design-reference/` with 27 Copilot screenshots (27 iOS screens + dashboard
variants + design system). Added to `.gitignore` — 22MB of binary images do not
belong in git history. Directory is kept local only.

## [refactor] Terminology — bucket → budget, expenses → transactions

[decision] "Bucket" is internal developer slang that leaked into the product.
No mainstream finance app uses it. Copilot, Monarch, and YNAB all use "Budget"
for a planned spending envelope. Changed everywhere in the UI.

[decision] "Expenses" → "Transactions" in navigation and page labels.
The industry term for a financial record is "transaction". Copilot, Monarch,
and YNAB all use "Transactions" for the list view.

**Scope of the rename — UI layer only. DB schema is unchanged.**
The `buckets` and `expenses` table names are not worth migrating — that would
require a schema migration with zero user-facing benefit.

### Routes renamed

| Old | New |
|---|---|
| `/buckets` | `/budgets` |
| `/expenses` | `/transactions` |
| `/api/buckets` | `/api/budgets` |
| `/api/buckets/[id]` | `/api/budgets/[id]` |

### Files renamed

```
app/buckets/           → app/budgets/
app/expenses/          → app/transactions/
app/api/buckets/       → app/api/budgets/
BucketsClient.tsx      → BudgetsClient.tsx  (prop: buckets → budgets)
```

### UI strings changed

- "Buckets" → "Budgets" in nav, headings, buttons, empty states
- "Expenses" → "Transactions" in nav, headings, section labels, empty states
- "No budget buckets yet" → "No budgets yet"
- Error boundaries: two pages had copy-pasted "Failed to load review queue"
  text — fixed to "Failed to load budgets" and "Failed to load transactions"

## [refactor] Colour system — indigo → blue

[decision] Copilot's primary brand colour is Royal Blue (~#2563EB), which maps
to Tailwind's `blue-600`. Replaced every `indigo-*` utility class across all TSX
files with the equivalent `blue-*` class.

Zero `indigo` references remain in the codebase. Confirmed with `grep`.

Affected: buttons, focus rings, nav accents, progress dot indicators, pending
banner, spinner borders, link colours, form focus states, error page buttons.

## [feature] lib/format.ts

Created `lib/format.ts` with `formatJMD()` and `formatCurrency()` helpers using
`Intl.NumberFormat`. Centralises all currency formatting — required by the P4
brief. The inline `J$${...toLocaleString()}` calls throughout the codebase will
be replaced with these helpers in the P4 UI pass.

```typescript
formatJMD(22180.64)   // → "JMD 22,181"
formatCurrency(22180.64, 'USD')  // → "US$22,180.64"
```

## [decision] P4 scoping — War Room Q&A

**Q1: When to fix the buckets_summary gap?**
Options: fix now in P3 chat / add as first task of P4 / defer to P6 analytics.

[decision] **Option 2 — add as first task of P4 brief.**
P3 is closed and deployed. Spend data IS the dashboard — deferring to P6 conflates
basic budget tracking with analytics. First task of P4 wires it up correctly, and
that moment is also when the bucket card redesign (progress bars, Copilot-style
layout) happens. One job: wire the data, render it properly.

**Q2: What should Phase 4 scope be?**
Options: iOS Shortcut only / broader (buckets_summary + category seeding + Shortcut)
/ buckets_summary + category seeding only (no Shortcut yet).

[decision] **Option 1 — iOS Shortcut only, buckets_summary as the first task.**
Category creation UI already exists in `/budgets` — seeding categories is a setup
action, not a missing feature. The Shortcut is the meaningful new capability for P4:
quick manual expense entry from the home screen without opening Telegram. Solves a
real daily-use problem (cash purchases, quick logging on the go).

Phase 4 scope locked:
1. Wire `buckets_summary` to the dashboard (redesign bucket cards with spend data +
   progress bars as part of the same task)
2. Build `/api/shortcut/upload` multipart endpoint (auth via `SHORTCUT_SECRET` header)
3. Build the iOS Shortcut (share sheet trigger → HTTP POST → notification)
4. Write `docs/ios-shortcut.md` setup guide

→ see `activity/phases/phase-4-shortcut.md`
