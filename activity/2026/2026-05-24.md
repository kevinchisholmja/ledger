All four phases share the same schema — getting it right first avoids painful

  → see docs/env-vars.md for the full variable reference

### Migrations
- [x] supabase/migrations/20240001 — enums
  Four enums defined:
  - `budget_period`: weekly, fortnightly, monthly, quarterly, annual
  - `expense_source`: telegram, shortcut, manual, csv
  - `expense_status`: pending_ocr, pending_review, confirmed, reconciled
  - `match_status`: unmatched, matched, ignored

  [decision] `expense_source` includes `shortcut` and `csv` even though those features
  are not built yet. Postgres enums cannot add values without a migration — defining
  them now avoids a breaking migration later when Phase 4+ is built.

- [x] supabase/migrations/20240002 — tables (categories, buckets, expenses, bank_entries)
  [decision] `expenses.amount` typed as `numeric(12,2)` not `float` — money should
  never use floating point arithmetic. Postgres numeric is exact.

- [x] supabase/migrations/20240003 — buckets_summary view + RLS policies
  `buckets_summary` uses `security_invoker = true` so it respects the calling user's
  RLS policies. However, when queried via Drizzle with the service role key, RLS is
  bypassed entirely regardless of this setting.
  [note] Every Drizzle query must include explicit `WHERE user_id = X` — never rely
  on RLS to filter data when using the service role. See CLAUDE.md.

- [x] supabase/migrations/20240004 — drop NOT NULL on expenses.amount
  [bug] The original schema had `amount NOT NULL`. Manual text entries from Telegram
  and failed-OCR receipts have no known amount at insert time — the user fills it
  in during the review step.
  [fix] Migration 20240004 drops the NOT NULL constraint. Drizzle schema must NOT
  use `.notNull()` on this column or TypeScript inserts will fail at compile time.
  → see supabase/migrations/20240004_amount_nullable.sql

## Phase 2 — Telegram Webhook + Claude Vision OCR

**Goal:** Accept receipt photos and PDFs via Telegram bot, extract structured data
using Claude Vision, store in Supabase. No UI yet — purely a data ingestion pipeline.

### Files created
- [x] app/api/telegram/webhook/route.ts — main webhook handler
  Handles two Telegram message types:
  - `message.photo` — compressed JPEG, always the last (largest) item in the array
  - `message.document` — uncompressed image or PDF sent via "Send as file"
  Both branches download the file, upload to Supabase Storage, run OCR, insert expense.

- [x] types/telegram.ts — TypeScript types for Telegram update objects
  (TelegramUpdate, TelegramMessage, TelegramUser, TelegramChat,
  TelegramPhotoSize, TelegramDocument)

- [x] scripts/set-telegram-webhook.ts — one-time registration script
  Run once after each production URL change. See docs/runbook.md.

### Supabase Storage
- [x] Created bucket `receipts` manually in Supabase dashboard (public bucket)
  [decision] Public bucket chosen — receipt images need to be accessible by the
  OCR route and the future review UI without requiring auth headers on every request.
  Storage path format: `{telegramUserId}/{uuid}.jpg`

  [bug] First version used path `receipts/{telegramUserId}/{uuid}.jpg`
  The Supabase storage client's `from("receipts")` already prefixes the bucket name
  into the URL. Adding `receipts/` to the filename produced a double-prefixed URL
  that returned 404 on every image load.
  [fix] Filename is now `{telegramUserId}/{uuid}.jpg` — no bucket prefix in the path.

### Claude Vision OCR
- [x] OCR prompt extracts: merchant, amount, currency, date, ai_suggested_category,
  confidence. Returns JSON only — no markdown fences, no explanation.

  [decision] Using claude-sonnet-4-6 — accurate enough for receipt parsing,
  significantly cheaper than Opus. The structured JSON output is reliable
  with Sonnet for well-defined extraction tasks.

  [bug] Initial model was `claude-sonnet-4-20250514` — this model ID was deprecated
  and returned a 404 from the Anthropic API with no clear error message.
  [fix] Updated to `claude-sonnet-4-6`.
  → see lib/ocr.ts

  [bug] PDF receipts sent via "Send as file" were silently ignored.
  The webhook only checked `message.photo`, not `message.document`.
  [fix] Added document branch — detects MIME type and routes PDFs to the same OCR
  flow. PDFs must use the Anthropic `type: "document"` API block, not `type: "image"`.
  Sending a PDF as an image block returns a 400 error.
  ```typescript
  const contentBlock = mimeType === "application/pdf"
    ? { type: "document", source: { type: "base64", media_type: "application/pdf", data: base64 } }
    : { type: "image", source: { type: "base64", media_type: mimeType, data: base64 } }
  ```

### Single-user design
- [decision] `LEDGER_USER_ID` environment variable pins all expenses to a single
  Supabase auth UUID. This is a personal app — there is no multi-tenancy, no login
  required to submit via Telegram. The webhook verifies its own identity via
  `x-telegram-bot-api-secret-token` header, not per-user auth.
